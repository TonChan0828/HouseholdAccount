## SEC-01：Next.js の既知の脆弱性

`package.json` と `package-lock.json` は Next.js を **16.3.5** に固定しています。本アプリは `app/` に画面を置く構成を採用し、ログインなどにサーバー上で実行する関数（Server Actions）を使っています。[根拠：package.json](../package.json)、[根拠：認証処理](../app/(auth)/actions.ts)

公式告知 GHSA-p3m5-59mp-jv5r は、この構成で CPU を過剰に消費させ、同じプロセスが別の要求を処理できなくなる問題を説明しています。16.3.5 は影響対象です。修正版は 16.4.1 です。今回、サービスを止める再現要求は送っていません。[Next.js サービス妨害告知 (2026/10), Impact / Patched versions](https://github.com/vercel/next.js/security/advisories/GHSA-p3m5-59mp-jv5r)

また、画像処理ライブラリ sharp は固定ファイル上で **0.35.4** です。公式告知 GHSA-2464-fhr4-w9xw は、glibc を使う Linux 上で画像最適化の依存ライブラリに遠隔コード実行の可能性があるとしています。sharp 0.35.5 以上が回避条件です。ただし、今回のソース検索では `next/image` の使用や画像アップロード機能を確認していないため、この攻撃経路が本番で成立するとは断定しません。[根拠：package-lock.json](../package-lock.json)、[Next.js 画像処理告知 (2026/10), Impact / Workaround](https://github.com/vercel/next.js/security/advisories/GHSA-2464-fhr4-w9xw)

**対処：** Next.js を少なくとも 16.4.1 以上の修正版に更新し、固定ファイルの sharp も 0.35.5 以上になったことを確認してください。その後、型検査、既存テスト、本番ビルド、認証と画面操作の確認を実施してください。

なお、型付き配列を返す `use cache` 関数の遠隔コード実行に関する別の公式告知もあります。本アプリでは該当関数を確認していないため、悪用可能な問題としては数えていません。[Next.js キャッシュ告知 (2026/10), Impact](https://github.com/vercel/next.js/security/advisories/GHSA-673q-mjm6-r5xr)

## SEC-02：ログイン後の外部サイトへの誘導

移動先を検査する `safeNextPath()` は、先頭2文字で `//` と `/\\` を拒否します。しかし、スラッシュの間にタブを挟んだ値を許可します。ログイン処理は許可された値をそのまま移動先に使います。[根拠：移動先検査](../lib/route-access.ts)、[根拠：signIn](../app/(auth)/actions.ts)

アプリの検査関数と、導入済み Next.js が移動先の解決に使う関数を呼び、次の結果を確認しました。表の `\t` は実際のタブ1文字です。HTTP 応答ヘッダーにタブを含められることも Node.js の検査関数で確認しました。

| 入力値 | アプリの判定 | Next.js が解決する移動先 |
| --- | --- | --- |
| `/households` | 許可 | `https://app.invalid/households` |
| `//example.invalid` | 拒否 | 既定の画面 |
| `/\t/example.invalid` | 許可 | `https://example.invalid/` |

攻撃者が用意したログイン画面へのリンクで `next=/%09/example.invalid` を指定すると、ログイン成功後に外部サイトへ誘導される経路があります。フィッシングに利用され得ます。これはセッションが外部サイトに自動送信されることを実証したものではありません。実アカウントを使ったブラウザでの一連の操作は未実施です。

**対処：** 制御文字を拒否してください。そのうえで、信頼する固定のオリジンを基準に URL を解決し、解決後も同じオリジンであることを検証してください。タブ、改行、バックスラッシュの組み合わせを回帰テストに追加してください。

## SEC-03：回数制限の失敗時に要求を許可する

`consumeRateLimit()` は設定不備を本番で拒否しますが、データベースへの問い合わせでエラーになると `true` を返します。このため、権限不備や関数の未適用などで制限用の問い合わせだけが失敗しても、ログインや招待発行の要求は許可され続けます。既存テストも、この許可動作を期待しています。[根拠：回数制限](../lib/rate-limit.ts)、[根拠：既存テスト](../lib/rate-limit.test.ts)

**対処：** 認証・招待などは問い合わせ失敗時に一時的なエラーとして拒否してください。可用性のために継続が必要な処理には、代わりの制限を明示的に設けてください。

追加で確認すべき点があります。ログインの制限キーは「メールアドレスとIPアドレスの組み合わせ」です。IPアドレスを変える攻撃には同一アカウントへの総量制限が働きません。また、`x-real-ip` を優先しているため、その値を配信基盤が必ず上書きするか確認が必要です。上書きを確認せずに、IPアドレスを偽装できると断定することはできません。[根拠：clientAddress / keyMaterial](../lib/rate-limit.ts)

Supabase（認証とデータベースを提供するサービス）への直接要求は、アプリ独自の回数制限を通りません。ただし、Supabase Auth 自体にも制限があります。本番の設定は未確認なので「認証要求を無制限に試せる」とは判断していません。アプリ側とサービス側の両方で対策を確認してください。[Supabase 回数制限資料 (2026/10閲覧), Rate limit behavior](https://supabase.com/docs/guides/auth/rate-limits)

## SEC-04：Excel の展開サイズに上限がない

取り込み処理はファイルの圧縮後サイズを5MBまでに制限します。しかし、ExcelJS（Excel ファイルの読み書きライブラリ）がブック全体を展開した後に、抽出した行数が500行以内かを確認しています。展開後の合計サイズ、文字列の長さ、シート数を読み込み前に制限していません。取り込み頻度の制限も、この処理にはありません。[根拠：取り込み入口](../app/(dashboard)/transactions/import/actions.ts)、[根拠：ブック全体の読み込み](../lib/import/parse-workbook.ts)

ローカルで、ファイルサイズ **14,653バイト**、抽出行数 **1行**のブックを作成しました。アプリの `parseWorkbook()` は、項目名が **8,388,608文字**の行を読み込みました。圧縮された小さな要求でも大きく展開されることを確認しています。後段の入力検証で項目名を拒否しても、展開時のメモリ消費は既に発生しています。サービス停止に至るまでの負荷試験は行っていません。

**対処：** 圧縮ファイルの展開後サイズとエントリー数を、読み込み前または読み込み中に制限してください。シート数と文字列長にも上限を設けてください。解析処理を時間・メモリ上限のある別プロセスで実行し、ユーザー単位の頻度制限を追加してください。通信本文のサイズ制限だけでは、この圧縮による増幅を防げません。

## SEC-05：公開レポート受付が本文を全量読み込む

ブラウザのコンテンツ実行制限に関する違反報告（CSP レポート）の受付は、未ログインで利用できます。受付処理は `Content-Length` が32KBを超えていれば拒否します。しかし、そのヘッダーがない場合は `request.text()` で全文を読み込み、その後に実際のバイト数を検査します。[根拠：公開ルート](../lib/route-access.ts)、[根拠：本文の読み込み](../app/api/csp-report/route.ts)

本文サイズを確定しない転送に対し、アプリが意図する32KBを超えるメモリ消費が先に発生します。本番の配信基盤による上限が別途働く可能性があります。外部から実際に何バイトまで受信できるかは未測定です。

**対処：** 本文を分割して読み、合計が32KBを超えた時点で読み込みを中止してください。配信基盤側にも本文サイズと時間の上限を設定してください。

## SEC-06：精算結果を直接登録する際の検証不足

サーバー処理は収支から精算結果を計算します。しかし、データベースの `settlements` テーブルは、精算結果である `snapshot` を任意の JSON として受け入れます。行単位でアクセスを制御する仕組み（RLS）の追加条件は、グループへの所属と、登録者が本人であることだけです。[根拠：精算計算](../app/(dashboard)/settlements/actions.ts)、[根拠：テーブルと追加ポリシー](../supabase/migrations/20260703151808_member_settlement.sql)

保存されている定義からは、同じグループの認証済みメンバーがデータAPIへ直接要求して、実際の収支と一致しない精算結果を登録できる設計と判断します。期間ごとの一意制約があるため、正しい精算の登録を妨げる可能性もあります。別グループのデータへのアクセスが可能という指摘ではありません。本番でのテーブル権限と直接登録の成否は未確認です。Supabase のデータAPIは、ブラウザから使う場合もデータベース側のアクセス制御を境界とします。[Supabase RLS 資料 (2026/10閲覧), Row Level Security](https://supabase.com/docs/guides/database/postgres/row-level-security)

**対処：** 認証済みユーザーによる直接追加を禁止してください。本人と所属を検証し、収支から結果を再計算するデータベース関数だけで精算を作成してください。JSON の形式だけを検査しても計算結果の改ざんは防げません。

## SEC-07：招待トークンがログに残る経路

例外の記録はクエリ文字列を削除しますが、パスはそのまま保存します。招待トークンは `/invite/[token]` のパスに含まれます。したがって、招待画面で例外が起きると、有効なトークンをログへ記録する経路があります。CSP レポートの URL 加工もパスを残します。[根拠：例外記録](../instrumentation.ts)、[根拠：レポートのURL加工](../app/api/csp-report/route.ts)、[根拠：招待画面](../app/invite/[token]/page.tsx)

招待トークンが有効な間は、ログを読める人が招待リンクとして利用できる可能性があります。実際にトークンが記録されたかは確認していません。

**対処：** 招待パスを `/invite/[token]` に置き換えて記録してください。一般の例外記録では、値を含む実パスよりもルートの定義を優先してください。CSP レポート内の URL にも同じ伏せ字処理を適用してください。

- CSP は設定例では報告だけを行い、実際のブロックをしません。強制する場合もインラインの JavaScript を許可しています。本番での有効化状況を確認し、要求ごとの一時値を使って許可するスクリプトを限定してください。今回の調査では、利用者の入力を HTML として直接挿入する処理は見つけていません。[根拠：CSP生成](../lib/security-headers.ts)、[根拠：設定例](../.env.example)
- パスワード変更と退会は、アプリ上では現在のパスワードや追加認証を要求しません。退会時のメールアドレス入力は誤操作防止であり、本人確認の追加要素にはなりません。退会用データベース関数も、ログイン中であれば直接実行できる定義です。セッションを奪われた場合の被害を抑えるため、重要操作の直前の再認証を検討してください。Supabase 側のパスワード変更時の再認証設定は未確認です。[根拠：設定画面の処理](../app/(dashboard)/settings/actions.ts)、[根拠：退会用関数](../supabase/migrations/20260618212650_0012_delete_own_account.sql)
- 画面上ではオーナーの脱退前に権限委譲を求めていますが、データベースのメンバー削除ポリシーには同じ条件がありません。直接要求で最後のオーナーが脱退できると、残ったメンバーが管理操作を行えなくなります。単一オーナーを維持する要件をデータベース側でも保証してください。本番での再現は未実施です。[根拠：脱退処理](../app/households/actions.ts)、[根拠：メンバーのポリシー](../supabase/migrations/20260618212726_0015_move_helpers_to_private.sql)

## 確認できた既存の対策

主要なデータアクセスにはグループ所属を確認する RLS があり、収支の登録者とグループを変更させない処理もあります。カテゴリは複合外部キーで同じグループ内のものに限定されています。管理者用の秘密鍵を使うクライアントはサーバー専用です。定期実行の入口には秘密値による認証があります。CSV 出力には、先頭の数式文字を無害化する処理があります。[根拠：RLS](../supabase/migrations/20260618212726_0015_move_helpers_to_private.sql)、[根拠：収支の不変条件](../supabase/migrations/20260920074241_0024_transaction_on_behalf_of.sql)、[根拠：外部キー](../supabase/migrations/20260716131725_0023_architecture_hardening.sql)、[根拠：管理クライアント](../lib/supabase/admin.ts)、[根拠：定期実行](../app/api/cron/recurring/route.ts)、[根拠：CSV出力](../lib/export.ts)
