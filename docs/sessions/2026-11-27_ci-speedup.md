# 2026-11-27 CI の実行時間短縮

## 目的
当初は Actions の利用枠の節約。途中で「確認内容を減らさず CI を2分で完了」を目標にした。
2026-11-27、現状(2分は未達)で区切る。

## 実施内容(PR #166)
- E2E のユーザーと家計簿をワーカーごとに分離(`E2E_WORKERS` 指定時だけ並列。seed も同じ値で実行する)
- E2E を12分割し、本番ビルドの確認を別ジョブに分離
- CI を verify / coverage / accessibility に分割
- Supabase の未使用サービスを除外し、E2E の準備を並行化

## CI の計測
| ワークフロー | 以前 | 分割後(1回) |
|---|---|---|
| CI | 約6分 | 112秒 |
| Database | 約3分 | 135秒(分割前の回は115秒) |
| E2E | 約23分 | 201秒(分割前の回は556秒) |

以前の値は private、今回は public で測定したため、差のすべてが変更の効果ではない。Mutation は未計測。
分割後の E2E は再実行なしで全成功。分割前の回は1件が再実行で成功(原因は未調査)。

## 残課題
- 2分の壁は E2E の準備時間(69〜110秒、主に `supabase start`)
- 手元の本番ビルドでは「500行のプレビュー」が単独でも5回中4回失敗(CI の本番ビルド確認は成功)
- `CLAUDE.md` Rule 5 の「`--workers=1`(CI と同条件)」は、PR #166 をマージすると CI の条件と合わなくなる
- 手元確認を push 前に行う共通スキルは設計書のみ(`~/.agents/docs/2026-11-27-verify-before-push-design.md`、未実装)
- ドラフト PR #164 は変更が重なる
